# Language Corner 双语角落设计规格

## 一、产品目标

将现有 macOS“俄语角落卡”升级为同一应用内的双语学习产品：

- 俄语继续解决词汇不足、搭配不足和主动提取慢。
- 英语集中解决“听得懂、读得懂，但轮到自己时不能自然脱口而出”。
- 英语和俄语共用桌面悬浮卡、复习算法、学习记录与通用交互。
- 两门语言拥有完全独立的内容库、每日队列、复习进度、诊断、提醒和训练目标。
- 不建立英俄互译卡，不让两种语言相互污染队列。

英语版不是四六级刷题工具。用户现有的无字幕《老友记》和纯英文阅读属于输入环境；产品负责把这些输入及高频日常语料转化为可主动调用的口语表达。

## 二、已选择的产品方案

### 不采用：复制一个独立 English Corner App

独立复制开发快，但会造成两套悬浮窗、设置、调度器、诊断和 Bug 修复长期分叉。

### 采用：一个应用、共享引擎、两套语言运行时

应用内通过语言切换进入英语或俄语。界面和算法共用，数据与内容隔离。这是维护成本、使用体验和数据安全最均衡的方案。

### 暂不采用：以 AI 自由对话作为英语主线

AI 对话将在二期提供交流压力和纠错。第一阶段先建立可调用的句块、搭配、回应和变式能力，避免用户在自由对话中反复使用少量简单表达。

## 三、品牌与兼容

- 产品界面名称改为 `LANGUAGE CORNER / 双语角落`。
- 为保护已安装应用、通知权限和本地数据，本次升级继续使用现有 bundle identifier 和 `/Applications/Russian Corner.app` 安装路径。
- 现有俄语 Application Support 目录、SwiftData 文件、UserDefaults 和所有学习进度保持原位。
- 不创建第二个并存 App，不要求用户手工迁移俄语数据。
- 折叠卡按当前语言显示 `EN` 或 `Я`，并显示该语言当天进度。

## 四、总体架构

### 4.1 语言配置

新增通用语言定义：

```swift
enum StudyLanguage: String, Codable {
    case english
    case russian
}

struct LanguageProfile {
    let language: StudyLanguage
    let displayName: String
    let shortLabel: String
    let defaultVoiceLanguage: String
    let fallbackVoiceLanguages: [String]
    let dictionarySourceLanguage: String
    let tokenizer: TargetLanguageTokenizer
}
```

默认语音：

- 英语：`en-US`，设置中可切换 `en-GB`。
- 俄语：`ru-RU`。

语音不可用时只影响朗读和听力题，不阻塞文本训练。

### 4.2 双语言运行时

`AppRuntime` 调整为：

- 一个全局悬浮窗和外观设置。
- 一个 `activeLanguage`。
- 两个独立 `LanguageRuntime`，分别持有 catalog、practice、diagnostic、progress、history 和 trial 数据。
- 切换语言时保存当前卡片索引，恢复目标语言当天队列，不重新生成另一门语言的队列。

### 4.3 数据隔离

俄语继续使用：

- `RussianCorner.store`
- `RussianCornerTrial.store`
- 现有俄语 UserDefaults 兼容键

英语新增：

- `EnglishCorner.store`
- `EnglishCornerTrial.store`
- `english.*` 命名空间的每日队列、话题、训练模式和目标设置

窗口位置、透明度、字号、显示器和折叠状态属于全局设置。每日卡数、当前话题、诊断、提醒和练习模式属于语言设置。

英语提醒默认关闭，避免升级后突然增加通知；用户可在设置中单独开启。俄语提醒保持现状。

### 4.4 通用内容模型

新增语言无关的训练模型，UI 和调度引擎改为消费通用模型：

```swift
struct StudyLexeme {
    let id: String
    let language: StudyLanguage
    let lemma: String
    let displayForm: String
    let speechText: String
    let phonetic: String?
    let partOfSpeech: String
    let glossZh: String
    let inflections: [String]
    let collocations: [String]
    let phrasalVerbs: [String]
    let wordFamily: [String]
    let morphologyNotes: [String]
    let memoryNotes: [MemoryNote]
    let exampleSentenceIDs: [String]
    let provenance: ContentProvenance
}

struct StudySentence {
    let id: String
    let language: StudyLanguage
    let promptZh: String
    let cueText: String
    let targetText: String
    let displayText: String
    let speechText: String
    let theme: String
    let lexemeIDs: [String]
    let dialogueAct: String?
    let register: String?
    let speakerRole: String?
    let expectedReplies: [String]
    let variants: [SentenceVariant]
    let provenance: ContentProvenance
}
```

现有 `Lexeme` 和 `SentenceCard` 通过 legacy adapter 映射到通用模型。原始俄语 JSON 不重写、不破坏兼容。英语内容直接使用通用 schema。

`MemoryNote` 必须区分：

- `verifiedEtymology`：可靠词源或构词关系。
- `morphologicalBreakdown`：现代构词拆分。
- `mnemonic`：谐音、故事、字形等记忆线索。

联想助记不能显示为真实词源。

## 五、悬浮卡交互

### 5.1 语言切换

- 卡片顶部提供 `EN / RU` 语言菜单。
- 切换后卡片宽度和桌面位置不变。
- 卡片主色允许按语言有轻微差异，但整体设计语言一致。
- 当前语言选择持久化，应用重启后恢复。

### 5.2 英语表达卡

英语卡以完整可说表达为主，孤立词卡为辅。

默认流程：

1. 显示中文意图、英语问题、图片描述或场景。
2. 3 秒内尝试说英语。
3. 揭晓自然表达并播放语音。
4. 点击任意英文单词查看解析。
5. 完成一个客观变式题或合理回应题。
6. 根据作答和反应时间进入调度。

最高熟练度不能只由自评产生。用户选择“完整说出”后，仍需通过最小迁移验证；验证失败按 `Hard` 或 `Again` 处理。

### 5.3 英文点击查词

英文分词器支持：

- Unicode 拉丁字母。
- 撇号缩写，如 `I'm`、`don't`。
- 连字符词。
- 所有格。
- 标点保留。

所有英文词都可点击。详情页按需显示：

- 音标与朗读。
- 当前词形、原形和词性。
- 当前句义与核心义。
- 高频搭配。
- 短语动词。
- 词形变化。
- 词族。
- 词根词缀。
- 熟词生义。
- 语域和使用场景。
- 当前句中的作用。
- 关联例句。
- 来源和审核状态。

正文始终是主角，解析在下方展开；窗口宽度不变，只向下延展，顶部保持稳定。

## 六、英语脱口而出训练链

每个核心表达至少经历五类训练：

1. **场景主动提取**  
   中文意图或英语问题出现后，用户先说，不先看答案。

2. **声音与表达核对**  
   揭晓后听美式英语，比较遗漏的句块、弱读和连读。

3. **槽位替换**  
   替换人物、时间、地点、数量、语气或动作。

4. **下一轮回应**  
   针对对方的下一句话作出自然回应，不只背原句。

5. **角色交换与迁移**  
   换成另一个说话人，或在相邻场景中表达同一意图。

调度触点默认使用：

`当天初学 → 次日主动提取 → 第 3 天变式 → 第 7 天接话 → 第 14 天迁移`

具体间隔继续由已有 Again / Hard / Easy 调度器调整。

### 6.1 自评边界

揭晓后使用四档：

- `3 秒内完整说出`
- `核心正确，但搭配或语气不自然`
- `揭晓后才想起来`
- `完全不会`

系统同时使用：

- 揭晓前反应时间。
- 是否播放或重复播放。
- 后续变式题是否正确。
- 合理回应题是否正确。

第二至第四档都会进入更短间隔。第一档只有在客观迁移题通过时才能映射为 `Easy`。

## 七、完整训练页

新增独立的英语微场景窗口，默认尺寸约 `760 × 680`，每天约 10–15 分钟。

一节训练包含：

1. 场景介绍：人物、关系、目的。
2. 双语理解：只解决意义，不要求背诵。
3. 英文文本：所有词可点击。
4. 撤掉中文：直接由英语激活场景。
5. 听音理解：文本隐藏，听后选择意图或回应。
6. 逐句跟读：支持正常速度和慢速。
7. 遮字复述。
8. 槽位替换。
9. 两至三轮微型对话。
10. 选出本节需要进入复习的表达。

界面显示当前训练目的，不用“第一遍到第六遍”的机械编号强迫用户重复；底层仍遵循逐步撤掉支架的方法。

## 八、《老友记》和阅读表达捕获

新增“捕获表达”入口，支持：

- 粘贴英文台词、句子或段落。
- 导入本地 `.srt`、`.vtt`、`.txt`、`.md`。
- 从文本中点击要保留的句子或句块。
- 自动识别候选词、缩写、短语动词和搭配。
- 补充中文意图、语域、说话角色和使用场景。
- 用户确认后进入候选库。

规则：

- 不联网抓取《老友记》剧本或受版权保护内容。
- 不复制、移动或改写用户原始文件。
- 导入只生成应用内部的派生候选。
- 自动提取内容先标记 `draft`，不得直接进入正式队列。
- 未附带原音频时使用英语系统语音；本期不切割或复制视频音轨。
- 未来可增加本地媒体时间轴绑定，但不作为首版依赖。

## 九、听力训练

英语默认美式发音，设置中允许英式发音。

卡片支持：

- 先听后看。
- 单句循环。
- 正常与慢速。
- 隐藏文本。
- 听后选择中文意图或自然回应。
- 跟读后再次播放。

完整训练使用已经理解的场景练习声音解码，重点观察：

- 弱读。
- 连读。
- 句子重音。
- 缩约形式。
- 语调和话轮衔接。

听力结果不能仅由“我听懂了”自评。选择题或回应题提供最低限度的客观证据。系统语音不可用时允许跳过，不计错误。

## 十、英语内容库

### 10.1 原始资料边界

只读资料根目录：

`/Users/Openclawworkspace/Library/CloudStorage/OneDrive-个人/Documents/20-语言学习与专业/！双语之路 英语母语者水平！`

已发现：

- 1427 篇 Markdown。
- 33 个 AI 整理、双链报告或类似派生文件。
- 32 个 conflict 文件。
- 318 个 `Roots_Data_Lite` 词根笔记。
- 大量方法论、生活讨论和备考策略，不属于直接训练语料。

明确排除直接投放：

- 所有 conflict 文件。
- AI 整理、双链报告、补链报告。
- 与英语学习无关的生活讨论。
- 只有激励观点、没有英语语料的直播笔记。
- 无来源、残缺、自然度存疑的表达。
- 把谐音或故事拆词当真实词源的内容。

可作为候选：

- “需要反复重复的单词”中的词与例句。
- 四六级高频词表。
- 词根词缀笔记中的词族关系和记忆线索。
- 英语表达、听力、阅读方法论。
- 用户后续主动导入的《老友记》台词和纯英文阅读句子。

### 10.2 首批正式内容

首批目标：

- 20 个高频日常场景。
- 200–300 个核心口语表达。
- 400–600 个关联词汇和句块。
- 每个表达至少包含一个自然回应或变式。
- 难度从中级日常英语开始，不投放 `hello`、`thank you` 等基础内容。

优先场景：

- 表达意见、同意和委婉不同意。
- 解释原因和补充细节。
- 请求、拒绝和协商。
- 澄清、确认和自我修正。
- 争取思考时间与维持话轮。
- 邀请、建议和改变计划。
- 电话、消息与临时沟通。
- 朋友交往和关系。
- 学校与工作。
- 情绪、冲突和安慰。
- 讲述过去经历。
- 描述正在发生的事情。
- 餐厅、购物、出行与生活服务。

### 10.3 质量闸门

内容继续使用 `draft / reviewed / verified`。

正式队列要求：

- 英文完整、自然、可直接说出口。
- 中文表达的是交际意图，不是机械逐词翻译。
- TTS 文本只包含可朗读英文。
- 缩写、语域和可能过时的表达有明确标签。
- 每张表达卡有场景、角色、交际意图和至少一种合理回应。
- 每张词卡至少关联真实搭配或场景句。
- 所有来源可追溯。

## 十一、词典和联网边界

现有 Yandex Dictionary 接口扩展为按语言查询：

- 俄语优先 `ru-zh`，必要时 `ru-en`。
- 英语优先 `en-zh`，必要时 `en-ru` 或英文结果作为降级。

在线结果：

- 只在用户点击词语时查询。
- 发送单词或词组，不发送完整私有学习记录。
- 缓存在本机。
- 始终标记“在线词典结果，未人工审核”。
- 不因在线返回而自动提升内容审核状态。

无网络、密钥无效或 API 不可用时，本地训练继续工作。

## 十二、诊断与每日反馈

此前通过的“客观小测为主、自评为辅”诊断升级改为通用能力，并分别运行于英语和俄语：

- 认词使用客观选择。
- 主动提取使用四档结果、反应时间和迁移题。
- 听力使用意图或回应选择。
- 搭配使用真实补全题。
- 口述只记录时间、活动和停顿，不假装判断发音。
- 错题进入对应语言的复习队列。

每日反馈按当前语言独立记录。视觉采用已经通过的轻量收尾卡设计。

## 十三、默认使用节奏

英语默认：

- 每天一个 10–15 分钟微场景。
- 5–8 张主动表达卡。
- 工作间隙完成听音、接话和变式复习。

俄语保持现有每日目标和队列。

两门语言不要求等量学习。用户可以单独调整每日卡数、完整训练频率和提醒。

## 十四、异常处理

- 英语资源加载失败：俄语模式继续可用。
- 俄语旧数据迁移或读取失败：停止双语升级数据写入并展示可恢复错误，不新建空俄语进度覆盖旧数据。
- 英语词典失败：显示本地词条或“在线暂不可用”，不阻塞学习。
- 导入文件解析失败：保留原文件不变，报告失败行和原因。
- `.srt` / `.vtt` 时间轴异常：仍允许按纯文本导入。
- TTS 语音缺失：文本和主动提取继续可用。
- 候选内容未审核：隔离在候选库，不进入每日队列。

## 十五、验收标准

### 数据安全

- 升级前后俄语原始资料哈希不变。
- 现有俄语学习事件、熟练度、诊断和当天队列可读取。
- 英语评分不会改变同 ID 的俄语内容状态。
- 英语资源损坏不会导致俄语模式无法启动。

### 双语交互

- 卡片内可切换 EN / RU。
- 切换前后窗口位置、宽度和折叠状态稳定。
- 两门语言恢复各自当前卡片和当天进度。
- 设置、记录、反馈和诊断明确显示当前语言。

### 英语训练

- 每个英文单词可点击。
- 英语 TTS 使用选定口音。
- 表达卡包含主动提取、变式和下一轮回应。
- “Easy”不能只靠一次主观点击产生。
- 听力题至少有一种客观理解验证。
- 完整训练可以从双语理解推进到隐藏文本听音和变式输出。

### 内容质量

- conflict、AI 报告和无关讨论不进入正式队列。
- 联想记忆与真实词源清晰区分。
- 首批正式表达全部为 reviewed 或 verified。
- 每个表达有来源、场景、语域和自然回应。
- 随机人工回读至少 50 张英语表达卡。

## 十六、本期不包含

- 自动联网抓取剧集字幕。
- 自动保存或上传《老友记》音视频。
- AI 发音打分。
- 以语音识别结果作为唯一评分。
- 英俄三向互译。
- 账号、云同步或跨设备同步。
- Windows、iOS 和 Android 客户端。
