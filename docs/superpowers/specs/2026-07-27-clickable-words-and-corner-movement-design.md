# Russian Corner 逐词解析与四角移动增量设计

日期：2026-07-27  
模式：MODE A 真实试用后的 P0/P1 修复  
状态：已获用户方向确认，等待书面规格复核

## 1. 目标

修复两个直接阻碍真实使用的问题，同时核对此前需求是否真正落地：

1. 句子揭晓后，每个俄语单词都可以点击，并在应用内查看与当前句子相关的词义和用法。
2. 角落卡可以通过拖动或卡片内入口移动到四个角，并在重启、收起和展开后保持位置。

本轮不重构调度、数据库、提醒、报告、诊断或原始语料系统。

## 2. 当前证据与缺口

### 2.1 逐词解析

`PracticeCardView.revealedAnswer` 当前使用一个普通 `Text(answer)`，没有词级交互。
首轮 35 张表达卡共有 97 个不同表层词形，但只有 13 张句子包含
`lexemeIDs`，总关联数只有 16。现有重点词关联无法支撑“任意词都能点开”。

结论：这是未实现，不是入口隐藏。

### 2.2 四角移动

现有代码已经包含：

- `FloatingCorner` 的四种枚举；
- `AppModel.corner` 的 `UserDefaults` 持久化；
- 设置页的“吸附位置”选择；
- `FloatingPanelController.origin` 的四角坐标计算。

但拖动结束后的 `recordDraggedScreenAndSnap` 只记录显示器，不计算新的角落，
随后再次按旧 `appModel.corner` 吸附。用户把卡片拖向其他角时，会回到旧角落。
卡片本体也没有明显的四角入口。

结论：底层坐标能力存在，但真实交互不完整。

## 3. 方案选择

### 方案 A：只让现有重点词可点击

改动最少，但 35 张句子中大多数词仍不可查询，直接违背用户要求。不采用。

### 方案 B：本地完整解析 + 可选在线扩展

为试用切片中每一个俄语词提供上下文解析；应用离线即可显示核心信息。
用户主动点击“在线词典”时，再打开该词原形的 Wiktionary 页面查看更多内容。

优点：

- 每个词即时可用；
- 不依赖账号、API Key 或网络稳定性；
- 能针对当前句子解释实际词形；
- 在线查询失败不影响学习；
- 只向外部词典发送用户主动查询的词元，不发送句子、进度或个人数据。

本设计采用此方案。

### 方案 C：Yandex Dictionary API 作为核心

Yandex Dictionary 当前仍提供词性、翻译和例子，但需要申请 API Key。它会增加
配置、密钥保存、错误处理和服务可用性负担。对当前 35 张试用句而言，收益不足以
覆盖成本。本轮不接入；若未来扩展到全量自由文本查词，再单独评估。

参考：

- Wikimedia MediaWiki Action API：
  https://www.mediawiki.org/wiki/API:Action_API
- Yandex Dictionary API：
  https://yandex.com/dev/dictionary

## 4. 数据设计

新增独立的句内词解析模型，不把所有基础词重新加入每日背词队列。

`SentenceWordAnalysis`：

- `id`
- `cardID`
- `tokenIndex`
- `surfaceText`
- `stressedForm`
- `lemma`
- `glossZh`
- `partOfSpeech`
- `morphology`
- `aspectPair`
- `government`
- `collocations`
- `usageNote`
- `lexemeID`
- `reviewStatus`
- `provenanceType`
- `qualityFlags`

规则：

- `tokenIndex` 按 `practiceRu` 中的俄语单词顺序计数；标点不计数。
- 一个词在不同句子中的用法不同时，保存不同的上下文解析。
- 已存在的重点词通过 `lexemeID` 复用完整 `Lexeme` 信息。
- 未作为独立背词卡投放的基础词、代词、介词和专名仍有本地解析，但不会进入
  `practiceLexemes`。
- 不适用的字段不显示。例如介词不显示体对，专名不显示支配关系。
- 状态仅为 `reviewed` 或 `verified` 才能进入试用。
- 不声称本轮内容经过母语者 `verified`。

## 5. 逐词交互

### 5.1 句子正文

- 揭晓后仍以完整带重音句子作为视觉主体。
- 每个俄语单词生成独立链接区域，同时保持自然换行和原标点。
- 可点击词使用轻微下划线或悬停底色，不使用大面积按钮样式。
- 当前选中词使用强调色，其他词保持正文颜色。
- 文本可通过辅助功能逐词朗读标签访问。

### 5.2 解析展开

- 点击任意词后，自动进入现有详情尺寸 `430 × 386`。
- 句子正文继续保留在主内容区，解析只占现有下方详情区。
- 解析区第一层固定显示：
  - 带重音词形；
  - 原形；
  - 中文核心义；
  - 词性和当前词形。
- 第二层只显示适用内容：
  - 名词性别、数和格；
  - 动词时态、人称、体和体对；
  - 支配关系；
  - 1–2 个搭配；
  - 当前句中的用法提示。
- “在线词典”是次级按钮，由用户主动触发，在默认浏览器打开
  `https://ru.wiktionary.org/wiki/<lemma>`。
- 再次点击当前词会关闭词解析；点击另一个词立即切换解析。
- 点“收起详情”清除当前选词；进入下一张卡也清除。
- 断网、URL 无法打开或系统没有默认浏览器时，只显示中文非阻塞提示，本地解析不受影响。

## 6. 四角移动交互

### 6.1 拖动吸附

拖动结束后：

1. 取得卡片所在屏幕的 `visibleFrame`。
2. 用卡片中心与屏幕中心比较横纵位置。
3. 映射为左上、右上、左下或右下。
4. 同时保存 `preferredScreenIdentifier` 和 `appModel.corner`。
5. 吸附到该角落的 18 点边距位置。

拖到另一块显示器时，两项设置一起更新。

### 6.2 卡片内快捷入口

标题栏增加四角位置菜单，图标使用系统 `square.grid.2x2`：

- 左上角
- 右上角
- 左下角
- 右下角

当前角落显示勾选。选择后立即移动，不要求打开设置页。设置页原入口继续保留。

### 6.3 持久化

以下操作不得改变已选角落：

- 应用重启；
- 显示/隐藏；
- 紧凑/详情切换；
- 收起/展开；
- 当天队列刷新。

## 7. 自动质量闸门

在现有 `trial-slice.json` 验证基础上增加：

- 35 张试用句的每一个俄语单词都恰好有一个上下文解析。
- `surfaceText` 必须与对应 `tokenIndex` 的原句词形一致。
- `stressedForm`、`lemma`、`glossZh`、`partOfSpeech` 和 `morphology`
  均非空。
- `speechText` 和句内解析不包含中文混入、Markdown 或括号变体。
- `reviewStatus` 只能是 `reviewed` 或 `verified`。
- 如果填写 `lexemeID`，该词必须存在并与当前词形或体对相符。
- 在线 URL 只允许 `https://ru.wiktionary.org/wiki/`。

## 8. 测试与验收

### 自动测试

- 词元切分保留标点并为每个俄语词生成可点击 token。
- 点击 token 能选择、切换和再次关闭。
- 切换卡片、评分、收起详情会清除选词。
- 词汇卡原有详情不受影响。
- `nearestCorner` 对四个象限和多显示器坐标均正确。
- 拖动落点更新并持久化角落。
- 卡片标题菜单的四个选项均能改变位置。
- 试用切片不存在未解析单词。
- 离线或外部 URL 打开失败不会阻塞卡片流程。
- 原有 225 项测试及打包安全测试继续通过。

### 应用级验收

- 实际启动 release `.app`。
- 从右上角分别拖到另外三个角，松手后不弹回。
- 退出并重启，位置保持。
- 用标题栏菜单依次切换四个角。
- 揭晓至少 5 张不同场景句，逐个点击其中所有单词。
- 检查长句自然换行、正文未被解析区挤掉。
- 检查至少一个名词、动词、介词、代词和专名的字段层级。
- 点击在线词典能打开正确原形；断网时本地内容仍完整。
