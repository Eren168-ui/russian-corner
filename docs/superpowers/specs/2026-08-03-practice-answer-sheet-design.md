# 练习答题卡与自由跳题设计

## 目标

在不占用练习正文和单词详情区域的前提下，让用户从顶部进度入口查看当天全部题目、识别漏评题并自由跳转。答题卡只负责导航，不替用户评分，也不在跳题时自动提交当前题。

## 交互设计

- 顶部现有 `1 / 17` 进度显示改为可点击入口，并增加九宫格图标与“打开答题卡”辅助说明。
- 点击后从进度入口弹出独立 Popover；它不改变主卡尺寸，不覆盖单词详情的固定布局。
- Popover 使用五列题号网格。每格显示稳定题号，并用视觉状态区分：
  - 当前题：蓝色描边。
  - 未开始：中性底色。
  - 已看答案但未评估：橙色圆点。
  - 已完成评估：绿色勾选。
  - 本日重练：题号旁显示 `R` 标记；原题保持“需要重练”的橙色状态。
- 底部汇总“已评估 / 待评估 / 总题数”，并提供图例。
- 点击任意题号关闭 Popover 并跳到该题：
  - 未完成题按正常流程作答。
  - 已完成题以只读复习状态打开，可查看答案和点击单词，但不会重复写入评估记录。
  - 离开一个已经揭晓但未评估的题时，只标记为“待评估”，不自动评分。
- 完成评估后仍停留当前题；用户点击“下一题”时，优先前往当前题之后的下一道待评估题，到队尾后从开头查找漏评题。
- 只有用户在所有题均已评估后再次点击“下一题”，当天练习才进入完成状态。

## 状态与数据

新增独立的会话导航状态，不再把 `currentIndex` 前面的所有条目假定为已完成：

- 每个队列条目使用 `题型 + 内容 ID + 当日出现序号` 形成稳定会话键，区分同一内容的原题与重练题。
- 状态为 `unseen / openedUnassessed / assessed / needsRetry`。
- 当前题号可以自由变化；“下一题”通过环形扫描寻找下一道未评估题，而不是简单执行 `currentIndex += 1`。
- 评估成功后先持久化原有复习事件，再更新答题卡状态；任一步失败都不伪装成完成。
- 当评分为 `Again` 时，沿用现有逻辑追加重练卡，并立即同步到答题卡。
- 当日导航快照按语言和日期保存在本地 `UserDefaults`。快照保存当前题、各题状态和队列签名；若队列变化或快照损坏，则安全丢弃导航快照并从真实复习记录重建，不影响核心学习数据。

## 组件边界

- `PracticeSessionNavigator`：维护稳定题号、状态、自由跳题和“下一道待评估”算法，不依赖 SwiftUI。
- `PracticeViewModel`：在揭晓、评估、重练和跳题时驱动 Navigator，并负责切换题目时清理当前临时视图状态。
- `PracticeAnswerSheetView`：只呈现题号、状态和点击事件，不执行评分。
- `PracticeNavigationSnapshotStore`：只保存当日导航快照，不修改原有复习数据库和语料。

## 边界与失败处理

- 跳题不会生成 ReviewEvent，也不会把题目算作完成。
- 已完成题只读回看，避免同一题重复评分和重复增加熟练度。
- 在线词典请求在跳题时取消，防止旧查询结果写入新题。
- 若答题卡打开期间队列追加重练题，网格自动追加题号并保持当前题不变。
- 关闭应用并重新打开后恢复当日答题卡；跨日自动建立新会话。
- 首版不加入题目收藏、拖动排序、批量跳过或自定义分组。

## 验收

- 可以从第 1 题直接跳到第 5 题，且第 1 题不会被自动评估。
- 第 5 题评估后仍停留，点击“下一题”进入第 6 题。
- 到队尾后，“下一题”会回到前面第一道未评估题。
- 已揭晓未评估的题在答题卡中有明确状态，并可返回完成。
- 已评估题可以只读查看答案与单词详情，不能重复提交。
- `Again` 产生的重练题出现在答题卡中。
- Popover 不改变主卡宽高，不遮挡单词详情。
- 重启应用后恢复当天状态；跨日不串用旧状态。
- 原有评估、复习调度、词典查询和 357 项现有测试继续通过。
